The Type-2 Grammar in the [[Language and Grammar#Chomsky Hierarchy|Chomsky Hierarchy]] is called as the **Context Free Grammar** and the language generated by such grammars is called a **Context Free Language**.

In a context free grammar the production rules are of the form -
$$
\alpha \rightarrow \beta
$$

where $\alpha \in N$ and $\beta \in (N \cup T)^*$.
# Constructing CFG for CFL
How do we prove that a given language $L$ is a CFL? This can be done in multiple ways:
1. If $L$ is regular, it has a Regular Grammar. Hence, it has a CFG and is a CFL. Otherwise,
2. Construct a CFG $G$ and show $L(G) = L$. Or,
3. Construct a **Pushdown Automata (PDA)** $M$ and show $L(M) = L$.

The language generated by a CFG can only have strings with finite length.

There are two ways in which a string can be generated from a given grammar -
1. Derivation
2. Parse Tree
# Derivation
The language can be derived either by doing **left-most derivation** or **right-most derivation**.
- In a left-most/right-most) derivation, the left-most/right-most non-terminal in every [[Language and Grammar#^e7b4fd|sentential form]] is replaced in a derivation.

**Example -** $G = (\{a,b\}, \{S,A,B\}, S, \{S \rightarrow AB, A \rightarrow aA | a, B \rightarrow b\})$. The string "aaab" can be derived in the manner -
1. $S \rightarrow AB$
2. $S \rightarrow aAB$
3. $S \rightarrow aaAB$
4. $S \rightarrow aaaB$
5. $S \rightarrow aaab$
# Parse Tree
A parse tree (or a derivation tree) is a tree representation of how a string is generated by a grammar.

The **frontier/yield** of a partial parse tree is a *sentential form*, i.e.
$$
\operatorname{frontier}(\tau) = (N \cup T)^*
$$

A parse tree can be constructed given a grammar by using left-most expansion or right-most expansion.

# Ambiguity
If any string in a language can be generated using multiple parse trees, we say that the grammar for that language has ambiguity and is called an **Ambiguous Grammar**. Formally we say that a grammar is ambiguous if 

$$
\exists w \in L(G)
$$

having:
- Two different parse trees
- Two distinct leftmost derivations, or
- Two distinct rightmost derivations

Example - $G = (\{id,+,*\},\{E,T\},E,\{E \rightarrow E + T | E * T | T, T \rightarrow id \})$ can lead to two different interpretations of the same string $id + id * id$.
- $(id + id) * id$
- $id + (id * id)$

If the leftmost and rightmost derivations of a grammar lead to the same parse tree, we say that the grammar is unambiguous.
## Problems with ambiguity
1. Multiple Meanings
2. Parsing Difficulties
3. Semantic Uncertainty
## Useful Aspects of ambiguity
1. Natural languages rely heavily on ambiguity. Ambiguous grammars are naturally more expressive.
2. Ambiguous grammars are often more simpler and hence more efficient.
3. Modern NLP systems resolve ambiguity statistically.
## Removal of ambiguity
Ambiguity can be removed by restructuring the grammar to -
1. Have operator precedence
2. Enforce associativity
3. Separate syntactic categories
4. Restrict recursive patterns

- To give something a higher precedence, it has to be the bottom-most production rule in the set of production rules.
- For a grammar to be right associative, the non-terminal should be on the right side of the production rule and vice-versa for left associativity.
## Theoretical Facts
1. Some CFLs are inherently ambiguous, meaning that any grammar for this language is always ambiguous no matter what.
2. Ambiguity doesn't mean non-determinism.
3. Ambiguity of CFGs is **undecidable**, meaning that no algorithm exists to determine if a CFG is ambiguous or not.
# Simplification of CFGs
Simplification of CFGs mean -
1. Removal of useless symbols (non-generating / unreachable)
2. Elimination of nullable productions
3. Elimination of unit productions
## Useless symbols
Useless symbols are either non-generating or unreachable,
1. In $A \rightarrow aA$, $A$ is a non-generating symbol as it will never terminate.
2. In $A \rightarrow aA | a, B \rightarrow bB | b$, $B$ is an unreachable symbol as it can't be reached from $A$.
## Nullable Productions
A null production ($\epsilon-$production) is of the form $A \rightarrow \epsilon$. If a null-production exists for any symbol except the starting symbol, then we can remove it for simplifications.
1. Identify all null productions.
2. Add productions by optionally removing the null productions.
3. Remove the null productions.
## Unit Productions
A unit production is of the for $A \rightarrow B$. These add no structure so we can always replace any occurrence of $A$ directly with $B$.
## Order of Simplification
$$
\text{Useless productions} \rightarrow \text{Null Productions} \rightarrow \text{Unit Productions} \rightarrow \text{Cleanup} 
$$

It is to be noted that a single scan of simplification may not achieve the desired target, so it can be possible that we need to repeat the above sequence multiple times.
# Normal Forms
Context-free grammars may appear in many equivalent but structurally complex forms. Normal forms standardize productions while preserving the generated language.
## Chomsky Normal Form (CNF)
A CFG is in CNF if every production rule is of the form -
$$
\begin{aligned}
A \rightarrow BC \qquad \text{or} \qquad A \rightarrow a \\[8pt]
(\text{and optionally} \,\,S \rightarrow \epsilon)\,\,\,\,
\end{aligned}
$$
## Greibach Normal Form (GNF)
A CFG is in GNF if every production rule is of the form -
$$
A \rightarrow a \alpha
$$

where $a$ is a terminal and $\alpha \in N^*$ is a string of non-terminals. GNF leads to:
- One terminal generated per step
- Direct PDA correspondence
- Top-down parsing

# Pushdown Automata
Intuitively a PDA is just a  [[Finite Automata and Regular Languages#Finite Automata / Finite State Machine|Finite Automata]] + an infinite memory Stack. 
- If this stack is restricted to only hold finite elements, then it could be incorporated inside the FSM itself. Thus such a PDA would act as an FSM instead and the accepted language would be a regular language and not a context free language.

 Mathematically, a pushdown automata is a septuple $(Q, \Sigma, q_0, F, \delta, Z_0, \Gamma)$, where -
1. $Q$ : Finite set of all states
2. $\Sigma$ : Input alphabet
3. $q_0$ : Starting state of the machine
4. $F$ : Set of all final/accepting states, $F \subseteq Q$
5. $\delta$ : Transition Function $Q \times \Sigma \cup \{\epsilon\} \times \Gamma \rightarrow Q \times \Gamma^*$
6. $Z_0$ : Initial stack symbol
7. $\Gamma$ : Stack alphabet

Similar to how a Finite State Machine has a deterministic and non-deterministic version, Pushdown Automata too have -
1. DPDA (Deterministic Pushdown Automata)
2. NPDA (Non-Deterministic Pushdown Automata)
## Properties
1. Expressive power of an NPDA is more than a DPDA's. Meaning that not all NDPAs can be converted to a DPDA. (NFA and DFA have the same expressive power)
2. By default PDA means NPDA.
3. Acceptance in PDAs can be handled in two ways – 
	- By final state – If string ends at a final state (Default) it is accepted, regardless of whether the stack is empty or not.
	- By empty stack – If stack is empty by the time the string is processed, it is accepted regardless what state it ended on.
	  
	Number of languages accepted by the final state method and the empty stack method are the same.
4. The transitions are denoted as - 

$$
\delta(\text{current state, current alphabet, stack head}) = (\text{next state, stack operation})
$$

More properties
- For the PUSH operation, the stack operation is written in the format - $\text{<new head>}\text{<old head>}$
- For the POP operation, the stack operation is written as $\epsilon$.
- In a PDA diagram the transitions are denoted in the format -
$$
\text{<current alphabet>}, \text{<current head>}|\text{stack operation}
$$

## PDA Normalization
A PDA is said to be in the normal form if every transition is of the following two types -
- $\delta(p,a,X) \ni (q,\epsilon)$ (pop operation)
- $\delta(p,a,X) \ni (q,YZ)$ (push two operation)

Normalization cases -
1. **Case 1 -** **If:** $\delta(p, a, X) \rightarrow (q, A₁A₂…Aₖ)$ where $k > 2$.
   
   Fix - Break it into a **chain of push-two steps** using new intermediate states $r_1 \dots r_{k-2}$ and new stack symbols $Y_1 \dots Y_{k-2}$.
   
2. **Case 2 -** Single Symbol Replacement $(k = 1)$
   
   Fix - Introduce a fresh state $r$ and fresh symbol $Z$:
	- First push $YZ$ (a two-symbol push)
	- Then immediately pop $Z$ via an $\epsilon$-transition
	  
3. **Case 3 -** Acceptance Normalization
   
   Fix - Convert to empty stack acceptance by:
	- Adding a new **bottom-of-stack symbol**
	- Adding transitions to **pop all remaining stack symbols**
	- Routing to a **unique accepting state** $q_f$
# CFG to PDA and vice versa
## CFG to PDA
Consider a grammar $G$, where 
- $V = \{A,B\}$
- $\Sigma = \{\alpha, \beta\}$
- $R = $\{A \rightarrow B\alpha, B \rightarrow \beta\}$

1. For every production in the grammar we add a state transition like -

$$
\begin{aligned}
\delta(q, \epsilon, A) &= (q, B\alpha) \\[2pt]
\delta(q, \epsilon, B) &= (q, \beta) \\[2pt]
\end{aligned}
$$

2. For every terminal in the grammar we also add a state transition like -

$$
\begin{aligned}
\delta(q, \alpha, \alpha) &= (q, \epsilon) \\[2pt]
\delta(q, \beta, \beta) &= (q, \epsilon) \\[2pt]
\end{aligned}
$$

# Important Examples -
<h6 class="question">Q1) Which of the following is a CFL?</h6>
1. $a^mb^nc^nd^m$
2. $a^nb^mc^nd^m$

<u><strong>Sol</strong></u>$^n$ -

Here $a^mb^nc^nd^m$ is a CFL as while processing $c$, we can pop $b$ from the stack and keep track of the number of pops. For $a^nb^mc^nd^m$ however this same thing isn't possible and thus it's not a CFL.
